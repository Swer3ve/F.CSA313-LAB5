## Newman-ы үр дүн

Collection нь 10 бие даасан тесттэй (тест бүр өөрийн setup-ыг pre-request script-ээр хийнэ), нийт **23 assertion**.

| Ажиллуулалт                         | Файл                      | assertions executed | assertions failed | exit code |
| ----------------------------------- | ------------------------- | ------------------- | ----------------- | --------- |
| PASS                                | `results/newman-pass.txt` | 23                  | 0                 | 0         |
| FAIL (`lab05-collection-fail.json`) | `results/newman-fail.txt` | 23                  | 1                 | 1         |
| DOWN (сервер унтарсан)              | `results/newman-down.txt` | 23                  | 23                | 1         |

- **FAIL:** 1-р тестийн статусын oracle-ыг зориуд буруу болгосон (201-ийн оронд 200 хүлээнэ). Үндсэн `lab05-collection.json` зөв хэвээр.
- **DOWN:** гаралтад `ECONNREFUSED` мөр байна. Энэ нь серверт холбогдож чадаагүй **интерфейсийн алдаа**; сервер хариу өгсөн боловч хариу нь oracle-ийн хүлээсэнтэй таарахгүй байхыг **oracle-ийн алдаа** гэнэ. Эхнийх нь тестлэгдэх системд хүрч чадаагүй, хоёр дахь нь систем (эсвэл oracle) буруу гэсэн үг.

## Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь сонголтуудаас төлөөлөх утгыг сонгох болон спецификаци зохиох алхам байлаа. Учир нь алдааны анги бүрийг ялгаж, нэг тест зөвхөн нэг шалтгаанаар унахаар утгыг сонгох ёстой байсан. Жишээ нь идэвхгүй оюутны тестэд хичээлийг урьдачгүй болгосноор алдааны шалтгаан зөвхөн оюутны статус байхаар хийсэн. Нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал аль нь буцахыг зааварт бичээгүй тул давхар алдааны хоёр хослолыг Postman дээр ажиллуулж тогтоосон. Үр дүнд сервер оюутны байхгүй байдлыг хичээлийн байхгүй байдлаас, оюутны идэвхгүй байдлыг урьдач нөхцөлөөс түрүүлж шалгадаг нь батлагдсан. Боломжгүй хослол ч таарсан: оюутан байхгүй бол түүний үзсэн хичээл гэж байхгүй тул "оюутан байхгүй + урьдач дутуу" гэсэн хослол утгагүй болно. Үүнтэй төстэй байдлаар байхгүй хичээлийн урьдач нөхцөл гэж байхгүй. Тест бүр өөрийн setup-ыг pre-request script-ээр хийдэг тул тестүүд бие даасан бөгөөд registrationID-ийн яг утгыг шалгахгүй, зөвхөн тоо эсэхийг шалгасан. Тестүүд серверийн логикт согог олоогүй, бүгд хүлээгдсэн үр дүнтэй таарсан. Харин collection-ыг export хийхэд baseUrl хувьсагчийн shared value (өмнөх хувилбарын initial value) хоосон байсан тул Newman дээр "request url is empty" алдаа гарч, мөн хадгалаагүй хүсэлтүүд хоосон URL-тэй export болсон нь ажлын хамгийн их сургамж болсон. Мөн DOWN ажиллуулалтаар ECONNREFUSED нь серверт хүрч чадаагүй интерфейсийн алдаа, FAIL ажиллуулалтаар унасан assertion нь oracle-ийн алдаа гэдгийг ялгаж ойлгосон. Exit code 0 ба 1 нь CI quality gate-ийн зарчмыг шууд харуулдаг тул автоматжуулалтын үнэ цэнийг ойлгосон.
